# Documents: user stories

Each story carries a security criterion (S) and an audit criterion (A). "Short-lived" means 300
seconds, everywhere in this feature.

## Doctor / Nurse

**US-1** As a clinician, I want to attach a scan or a letter to a patient's record so that the
evidence sits with the record it supports.
- Acceptance: `POST /api/v1/patients/{id}/documents` returns `201`; the row is `PENDING` until the
  scan returns; the file appears in the patient's document list only when `CLEAN`.
- S: `document:create`; tenant and `patient_id` resolved server-side; the object key is generated by
  the server and the client never sees or supplies it (`05-tenant-isolation.md` §243).
- A: `document.uploaded` with actor, tenant, `document_id`, `patient_id`, `size_bytes`, `sha256`,
  `request_id` — never the filename and never the content (`12-data-classification.md` §3).

**US-2** As a clinician, I want to view a document through a short-lived link so that I can check the
source without the link being forwarded usefully.
- Acceptance: `GET /api/v1/documents/{id}/url` returns a URL that expires 300 seconds after issue;
  after expiry S3 returns `403`.
- S: minted only after an authorisation check on the document row; TTL exactly 300 s; bound to the
  exact key; issued per request, never cached or stored (`05-tenant-isolation.md` §243).
- A: `document.viewed` with actor, `document_id`, purpose and `request_id`; the rejection case is
  audited too, because a refused mint is a signal.

**US-3** As a clinician, I want to know that a document failed its scan so that I stop waiting for it.
- Acceptance: `scan_state` becomes `INFECTED` or `ERROR`; the document is quarantined and never
  rendered; the UI shows the state and the reason code.
- S: a quarantined object is never served — R5 blocks the mint for every state except `CLEAN`.
- A: `document.scan_failed` with the verdict class, engine version and quarantine location; the
  Clinical Safety Officer is notified (`11-tga-inbox-pipeline.md` §9, §10).

## Administrator

**US-4** As an administrator, I want to upload supporting paperwork for a registered patient so that
the clinic's file is complete.
- Acceptance: same endpoint and same validation as US-1; no bypass path exists for the admin role.
- S: `document:create` scoped to the tenant; the upload validation pipeline is not role-dependent.
- A: `document.uploaded` with `actor_role = ADMINISTRATOR`.

**US-5** As an administrator, I want to remove a document uploaded in error so that the record is not
cluttered by my mistake.
- Acceptance: the row is soft-deleted (`deleted_at`); the request is refused if the document is
  referenced by an approval record.
- S: no hard delete exists — the app role holds no `DELETE` grant and the object moves to a retention
  prefix by lifecycle rule (`04-database-erd.md` §3.9, §6).
- A: `document.deleted` with actor, `document_id` and reason code.

## Clinical Safety Officer

**US-6** As the Clinical Safety Officer, I want an alert when a document fails its scan or when its
stored hash stops matching, so that I can decide whether a patient safety event exists.
- Acceptance: alert names the tenant, `document_id`, the failure class and the engine version; no
  content is included.
- S: alerting path is read-only and tenant-scoped; the quarantine bucket has a separate IAM boundary.
- A: the alert and the containment action are both recorded; hash mismatch on retrieval raises an
  alert (`11-tga-inbox-pipeline.md` §8).
